# Konpeki

Use [AUTHORING.md](AUTHORING.md) when creating or revising slide content or design.
Use [README.md](README.md) for setup, component contracts and checks relevant to
the code you change. Examples and specimen geometry are not design requirements.

Keep drafting, editing and presentation on Konpeki's shared composition canvas.
Retained React/SVG examples are presentation-runtime-independent drawing
references, not a parallel deck runtime. New product behavior must use the
shared composition.

For implementation requests, continue through rendering, inspection and repair
of consequential issues within the brief. Local source edits, previews and checks
do not need separate approval. Stop at drafts only when the user requests that
checkpoint; ask when missing information prevents a faithful result.

Scale verification to the change using [README](README.md#verification). For
visual changes, inspect actual affected renders; passing tests is not visual review.

For new examples, save the exact initial request and subsequent prompts in
`slides/<name>/PROMPT.md`; keep source facts and asset provenance beside the deck.
Do not present reconstructed or adaptation prompts as original requests.
Do not push or publish without permission.
